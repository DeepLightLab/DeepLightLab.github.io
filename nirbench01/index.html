NIRBENCH · Benchmark v0.1

Deep learning
for NIR spectra

NIRBENCH compares how well deep learning architectures designed for NIR spectral analysis generalize across different chemometric tasks. Version 0.1 compares out-of-the-box performance (no hyperparameter optimization) with two baselines: a fully optimized PLS (preprocessing and LV) and the TabPFN-3.5 foundation model.

HOW TO READ THIS

A common scale for different targets.

Rank models by test RMSE within each dataset, convert each rank to a 0–100 score, then average across shared datasets.

100 × (M − rank) / (M − 1)

M is the number of models included. Ties receive an average rank. A score of 100 means first place on every dataset in this comparison.

Changing the number of models displayed changes the score. By default, the comparison includes all 13 DL architectures, PLS and TabPFN-3.5.

03 / THE PROTOCOL

One test split. A clear comparison.

Model selection happens inside the training data. Held-out test labels are used only for final evaluation.

01

Load fixed splits

Use the same stored training and test samples for every model. The shared loader removes ID columns and rows with missing values.

02

Transform from training data

DL and TabPFN-3.5 use training-fitted standardization. PLS evaluates spectral preprocessing inside CV; MSC references and PLS scaling use only each fold’s training rows.

03

Fit, then repeat

DL models and TabPFN-3.5 use ten final seeds, 12345–12354, on the full training split. PLS uses one final fit after preprocessing and latent-variable selection.

04

Score in original units

Predictions are expressed in the original target units before computing RMSE and R². DL and TabPFN-3.5 report mean and sample standard deviation across final runs.

13 DL architectures

CV chooses the epoch budget

Five shuffled folds, seed 12345. Record the best validation-loss epoch in each fold, then use their median. CV allows up to 600 epochs with early-stopping patience 100.

The ten final fits use that fixed budget, with no validation split or early stopping. Model-specific optimizers and schedules are retained. There is no full hyperparameter optimization for the DL architectures and they are instantiated with the original paper's hyperparameters (out-of-the-box evaluation).

TabPFN-3.5

Pretrained weights, full context

No cross-validation or epoch selection. The full standardized training set becomes context for the pretrained regressor. Ten seeds vary its internal ensemble.

Its training metrics are left empty because those labels are in the model’s context. Test metrics use the same output schema as the DL models.

PLS regression

CV chooses preprocessing and latent variables

The golden standard of chemometrics. Five-fold training-set CV jointly searches nine variants: raw spectra, SNV, MSC, first/second Savitzky–Golay derivatives, and SNV/MSC followed by either derivative. Each variant searches 1–20 latent variables.

The pair with the lowest pooled out-of-fold RMSE is fitted on the full training split. Test RMSE and R² are reported for this single final fit.

What to keep in mind when reading the results

Run variability: standard deviation describes variation across model seeds on a fixed split. It does not measure uncertainty across new sample collections or alternative test splits.

Predictions and plots: saved prediction files and scatter plots represent the last final run. The metric tables summarize all final runs. Note that individual model hyperparameter optimization on a given dataset (not done here) is bound to improve its performance.

Common input, architecture-specific processing: For all DL models and TabPFN-3.5, the spectral features and target values are standardized using parameters fitted on the training data. CNNs add a channel dimension; MarkSpectra selects wavelength marks; TabPFN-3.5 also uses internal preprocessing. A dataset may already contain preprocessing, such as the SNV pear configuration.

Scope: performance describes these fixed splits and benchmark implementations. The architecture comparison does not establish that one model is best for all spectroscopy tasks. The objective of the benchmark is to compare how different DL architectures generalize to different chemometric tasks (independently of their performance on a specific dataset).

04 / THE MODELS

Neural network implementations using TensorFlow/Keras.

Thirteen implemented DL architectures based on their original papers, a classical reference, and a pretrained tabular model. ResidualSpectra, Spectraformer and SpectraTr were adapted for regression purposes. 1D-CNNs are presented in three different variants. Each model is an independent Python file that you can download and try on your own data. If you have read about DeepSpectra or SpectraNet32, you can now test those models on your data.

FUTURE VERSIONS

Measure how models generalize...

The main purpose of NIRBENCH is to curate a large pool of datasets / chemometric tasks based on publicly available data, and guidelines that researchers can use to test their DL models aimed at spectral analysis in the NIR (and other spectra) range. We also implemented and share several DL models published in the area of NIR chemometrics as a starting point for the benchmark. Many of these models are described in the original papers, but a ready-to-use implementation is not usually offered by the authors. Now you can simply download the model .py file and test it on your own data with a bit of extra coding. Over subsequent versions of NIRBENCH, we will share the implementation of more DL architectures and will increase the number of datasets. We also plan to build an optimization pipeline (HPO) that can be applied to all DL models, in order to improve their general performance. This is already in motion as a partnership with colleagues from LabCom Aiol (Artificial Intelligence and Optics Laboratory) and ChemHouse Research Group from UMR ITAP (INRAE).

Current results indicate that TabPFN-3.5 (a foundation model developed for tabular data) provides better (out-of-the-box) performance in NIR-based prediction than most NIR-specific DL architectures built for NIR analysis and even an optimized PLS. This is very interesting because TabPFN was not specifically designed for the highly collinear and structured nature of spectral data, yet it has shown surprisingly strong performance across multiple chemometric datasets. Based on Reiter et al. (2026), a previous version of TabPFN also seems to perform better for this type of data than other ML models that are usually strong at regression tasks.
